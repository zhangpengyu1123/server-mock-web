## 二、七个界面（六屏业务 + 系统）

参考图正好 7 个页签，我们的平台正好 6 屏 + 系统，于是**一一对应**：

| 页签 | 屏 | 覆盖的功能（§5 全套） |
| --- | --- | --- |

| 引 擎 ENGINE | `flow` | 接口清单 · 8 档 HTTP 状态 · 延迟 scrub 0–3000ms · **字段定制**（9 类型 / 4 取值方式 / **五类规则**：固定·自增·单次生效·条件·随机）· 插入**人机交互** · 触发一次 · **审计日志**（过滤器 + 搜索 + 报文展开 + 命中说明 + 放行/拒绝） |
| 标 本 SPECIMEN | `ne` | 属性/架构/类型/厂商/版本/软件名 · 归属与**成组**（建组/加入）· **复制网元** · **升级流程**（增删上下移，自动/手动/**人工**，人工步骤带 `human-confirm` 交互规格，执行时停在闸门）· **参数校验**（增规则 + 执行 + 逐项状态） |
| 受管域 MANAGED | `omp` | 账号（角色/授权网元/启停）· **创建账号** · **一体化任务**（gauge 进度、逐步状态、人工步骤提示、推进）· 任务**关联站点** |
| 库 房 PACKAGE | `lcm` | 软件包（类型/所属网元/厂商/版本/大小/MD5）· **校验流程**（MD5/签名/依赖 + 状态标记）· 移除（可撤销）· **与网元管理平台共部署** |
| 虚 层 STACK | `vlp` | **平台版本**切换 · **CPU 配额**（scrub + 液面 gauge）· **主副站点互斥** · **升级流程** 4 步推进/重置 · **软件包校验** 4 项 + 全部执行 |

## 三、键盘就是主交互（参考图的 `W S 选择`）

| 键 | 行为 |
| --- | --- |
| `W` `S` / `↑` `↓` | 在左列移动菱形光标（选中即加载详情） |
| `Enter` | 确认：进入该条（并在标本屏推进升级流程） |
| `Esc` | 返回：先退出输入框 → 再清空选中 |
| `1`–`7` | 直接切界面 |
| 任意键 / 点击 | 跳过启动自检 |

在输入框内时 `W/S` 不劫持（只处理 `Esc` 失焦与表单提交），否则就没法打字了。

## 四、动效（只用本项目技能预设）

- **Hover**：列表块/按钮位移 1–2px + 硬投影缩短，`120–200ms`。
- **Enter**：`iris` 光圈揭幕（自检结束，主界面从中心展开）、`develop` 显影（切屏）。
- **数字**：`countUp` 只给「审计记录 / 累计命中」——值变了才滚，避免每 2.6 秒重放。
- **选择**：菱形光标 `steps()` 呼吸闪烁（还原参考图那种"待命"感）。
- **异步**：所有 >300ms 的操作走 `MP.btn.loading()`（签发/重签/触发/校验/推进/执行），最短 300ms。
- **微交互原语 9 个**：`holdConfirm`（按住启动）· `fuseButton`（停止服务/移除包）· `velocitySwitch`（系统开关/共部署）·
  `gauge`（任务进度、CPU）· `statusMark`（校验、参数校验）· `scrub`（延迟、CPU）· `segmented`（审计过滤）·
  `latticeLoader`（校验进行中，完成后即替换）· 另有 toast。
- `prefers-reduced-motion` 全量归零（含光标呼吸与自检进场）。

## 六、边界与出处（如实说明）

- **不复制游戏素材**：纹章与 `BLACKBOX` 字标是本项目**自绘 SVG / 自定文案**，没有使用 YoRHa 徽标或游戏内素材；
  启动日志的句子按参考图的**句式与节奏**改写为平台自检项。这是"复刻界面语言"，不是搬运资产。
- **字体**：离线只用系统字体栈（微软雅黑 / 苹方 + 等宽）。参考图的 CJK 是游戏自制宽体，这里用字距与细字重逼近。
- **数据**：全部前端模拟（`_shared/domain.js` 种子 + 定时器）。接真实后端时替换 domain actions 即可，视图层不用动。
- **窄屏**：参考图只有 16:9 一种形态。≥1440 按参考比例；1200 / 900 / 640 三档是我按内容需要合理延伸的（`≤900` 单列堆叠、状态面板下沉、指令条换行），并已测无横向溢出。

## 八、R2 重构：两种时间（**本次意图 = 改流程**，视觉沿用）

> 按 oil-ui-pro 的规矩，先写意图：**这次是改流程，不是优化视觉**。纸面 / 硬投影 / 打孔线 / 菱形光标那套**一个字没改**，
> 改的是「什么东西在什么时候出现」。所以下面的判断都以流程为准，视觉效果只做新增件。

### 8.1 为什么要改

用户原话：*"7 个模块全部堆在界面上，但它们有依赖关系；真正给用户呈现的只有 mock 的启动，和启动后的操作。那些编辑的活都不是在运行中干的，还有新增接口。"*

按手册「改流程」的第一步——**亲手动一遍并计数**（1600×900，同一台机器）：

| 指标 | 改前 | 说明 |
| --- | --- | --- |
| 启动主行动的纵向位置 | **913px** | 首屏 900 高，必须滚动才看见；同屏还堆着 4 个面板 |
| 找到「审计日志」要滚多远 | **1532px** | 它是引擎屏中列的第 **11** 个面板（前面是接口、配方、5 张字段卡、人机交互） |
| 平级页签 | **7 个** | 运行与配置同权，界面没回答"现在该做什么" |
| 全局运行状态 | 只有右侧小字「在服 0/3」 | 平台最重要的状态不显眼 |
| 运行中是否禁止编辑 | 不禁止 | 边跑边改，改了什么算不算生效也没说 |

### 8.2 按五种原因定位

1. **做决定的地方没有信息**：启动要判断"证书/能力齐不齐"，可按钮在页面最底，能力卡片在它上面两屏。
2. **功能长在用户不会去找的地方**：运行时最需要的触发与审计，被压在编辑面板最下面。
3. **流程形态与任务不匹配（主因）**：平台其实有**两种时间**——准备时（离线配置）与运行时（服务在跑）。原来那 7 个是**配置分类**，却被当成了导航。
4. **系统知道的事让用户再做一遍**：系统明明知道证书/能力是否齐备，却要用户自己逐屏核对。
5. **状态看不见**：运行/停止是第一状态，只藏在右侧面板的一行小字里。

### 8.3 新结构：两种时间 → 两个模式

```
[运行台] [准备台]                    ← 模式开关（页签条左侧两块）
  ├─ 运行台：  运行 · 审计 · 闸门 · 系统        （运行时只看这 3+1 个）
  └─ 准备台：  接入 · 接口 · 网元 · 平台 · 库房 · 虚层 · 系统
```

**首屏 = 运行台**（这是运行时唯一入口）：
1. **运行状态大块**：`运行中 / 已停止` + 地址 · 能力数 · 请求数 + 主行动（按住启动 / 停止）。
2. **就绪链**：`① 端点已登记 → ② 证书已签发 → ③ 能力已挂载 → ④ 服务运行中`。
   完成的打勾；**未完成的那一步高亮**，点它直接跳到准备台对应位置（运行中会被拦，提示先停止）。
3. **触发台**：选接口 → 触发一次，下面给出状态/延迟/命中/是否插了人机交互。
4. **实时审计**：最新请求 + **待放行卡片内联放行/拒绝**；右上「全部记录」进审计页。

**准备台 = 离线编辑**：六屏原样保留，但**运行时被锁**——页签变灰加删除线，点击提示"停止后才能编辑"，
页眉常驻「运行中 · 准备台已锁」+ 一键「停止并进入准备」。

**内容迁移表**（谁搬去哪）：

| 原来住的地方 | 现在住的地方 |
| --- | --- |
| 接入屏底部的「伺服 / 启动服务」 | **运行台 · 主行动** |
| 引擎屏的「触发一次」 | **运行台 · 触发台** |
| 引擎屏的「审计日志」 | **运行台 · 实时流** ＋ **审计页**（完整过滤/搜索/详情） |
| 引擎屏的「放行 / 拒绝」 | **运行台 · 待放行卡片** ＋ **闸门页**（集中处理） |
| 其余全部编辑能力（登记/证书/能力/配方/字段/规则/交互/网元/账号/包/虚层） | **准备台 · 六屏** |

### 8.5 验证

```
oracle（功能 30 条 + 动效 + 微交互 + 按钮动效 + 离线 + 语法）        V8 通过
浏览器 5 档(375/768/1024/1440/1600) × 10 屏                          全部无横向溢出、pageerror = 0
模式：运行中点「准备台」→ 被拦 + 提示；页眉「停止并进入准备」→ 停服并落到接入屏 ✓
准备台·接口屏：已无触发按钮、无审计面板 ✓（运行时的东西不在编辑区）
运行台·停止态：主行动出现、就绪链高亮下一步、触发台显示"服务停止中" ✓
布局实测：.work 56→1544、右列 1104→1544（440 宽贴右）、锁提示 262×28 横排 ✓
```

**本轮修掉的 4 个布局/接线问题**（都是自己验证时抓到的）：

1. **隐藏页签仍占位** —— `[hidden]` 的 UA 规则被 `.tab{display:flex}` 覆盖 → `.tab[hidden]{display:none!important}`；
2. **舞台隐式网格列被页眉内容撑宽**，右列被裁掉 56px（视觉上一眼就看出状态面板被切）→ `.stage{grid-template-columns:minmax(0,1fr)}`；
3. **锁提示被挤成竖条**（`margin-left:auto` 在满排页签里拿不到宽度）→ 移入页眉 + `white-space:nowrap`；
4. **页签被压窄导致标题截断**（"运.."）→ `.tab{flex:0 0 auto; min-width:132px; max-width:210px}`。

5. **微交互回调名写错，主行动一直空转（最严重）** —— holdConfirm 的完成回调是 onConfirm、fuseButton 是 onCommit，
   我写成了 onDone：按住 0.9 秒进度条会走满、按钮会进 is-done，**但服务从来没启动过**。
   之前只验证了「按钮在不在」，没验证「按下去有没有效果」，所以一直没暴露。现已在 V8 修掉 5 处；
   V6 / V7 用的是正确名（已核对），不受影响。这条是本轮走查最大的收获：先按流程真按一遍。

> 一行 req 拼错、事件监听没挂、SEL.ne() 语义误解这三个更早的坑，是 R1 阶段抓的，已记在上文。

### 8.6 评审

- **视觉**：本轮不动视觉语言，新增件（模式开关 / 就绪链 / 实时流 / 待放行卡）按 100% 截图看过，未做打分式视觉评审（本轮不涉视觉改动）。
- **信息架构**：派出 1 名**独立 UX 走查**（不看源码、不看本说明，只从界面自行推断目标，完成"启动 → 触发 → 放行"）。结论见 §8.7。
- 未做：多方案对比页（用户已明确指向"按依赖关系重排"，不需要发散）。

### 8.7 UX 走查结论

**派出的独立子代理本轮未返回结果**（会话跨了 16 小时，目标已不可寻址），因此下表由主 Agent
按同一口径**亲自用真实鼠标操作走了一遍**（不是调 API 假装点击），并如实标注为「未独立评审」。

走查路径：落地（运行中）→ 停止并进入准备 → 回运行台 → **按住 1.1 秒启动** → 触发一次 → 放行待放行 → 停止。

| 项 | 实测 |
| --- | --- |
| 点击次数 | **6**（停止、切模式、按住、触发、放行、停止） |
| 模式切换 | **1** |
| 页签切换 | **0**（除模式外没有跳屏） |
| 滚动 | **0** |
| 页面报错 | **0** |

**摩擦点（5 条，按严重度）**

1. **落地是「运行中」，想体验启动得先找停止入口**（藏在页眉锁条里）。对「我就是来启动的」第一次使用者，多了一步反向操作。
   → 可选：运行中时在 hero 里同时给「重启」，或把种子数据默认成停止态。
2. **就绪链第 4 格「服务运行中」与 hero 的启动按钮语义重叠**（一个是状态、一个是动作），文案一度出现过循环提示「还差一步：服务运行中」——已修，现在只说前置 1–3 步。
3. **待放行卡片挤在「实时审计」面板里**，视口内可见没问题，但同时来 3 条就会把实时流挤出屏幕。→ 可选：待放行单独占一块，或右上角折叠计数。
4. **触发台的接口下拉只列「启用中」的接口**，停用的接口在运行时看不到，也就看不出「某接口为什么不可触发」。→ 建议下拉列出全部、停用的标注已停用。
5. **停止状态下没有任何「你正在准备态」的常驻标记**（锁条只在运行时出现），从运行台切到准备台后，缺一个持续的模式提示。

**如果只改一处**：在运行台 hero 加「重启」。
理由：这轮重构建立的真实使用节奏是「准备台改配置 → 回运行台重启生效」，
「重启」是把两个模式接起来的那个动作，现在必须走「停止 → 再按住启动」两步。

### 8.8 已知边界与假设

- **假设 1（运行中禁止编辑）**：用户说"编辑的活都不是在运行中干的"，因此实现为**硬锁**（不是只读提示）。
  如果真实产品允许热改接口（比如改完提示"需重启生效"），把锁换成"可编辑但标注未生效"即可，结构不用动。
- **假设 2（默认落在运行台）**：首屏即运行时视角。若主要用户是"每天来配一次、跑一天"，也可反过来默认准备台。
- 演示种子里 `port-1` 是运行态，所以打开就是「运行中」；要看启动链路，点一次「停止并进入准备」→ 回运行台即可。

## 十、R5：三套配色可切（暖纸 / 纯白 / 蓝黑）

用户原话：*"三种界面颜色风格：当前的尼尔风格，还有 v7 的纯白风格，再新增一种是 Codex 那种蓝黑色专业风，然后可以切换。"*

### 10.1 做法：先把颜色彻底 token 化，再换皮

换主题最容易翻车的地方是**硬编码色残留**（白底上留一块深色块，或者深底上留一段黑字）。所以顺序是：

1. **清点**：`app.css` 里有 **62 处** `rgba(42, 41, 35, …)`（都是"墨色 + 透明度"），另有页签底、边框、舞台底、启动屏底等 6 处裸 hex。
2. **token 化**：`rgba(42,41,35,…)` → `rgba(var(--ink-rgb),…)`；裸 hex → `--tab / --tab-hi / --charcoal-bd / --void / --boot-bg / --key-bg`。
   改完 `rgba(42, 41, 35` 计数为 **0**。
3. **三套变量组**（`html[data-theme]`，`:root` 即暖纸）：

| 主题 | 底 | 面板 | 主行动 | 强调 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `nier` 暖纸 | `#c8c3ac` | `#ccc7af` | `#3e3c34` | `#8c3a2e` | 参考图取色，默认 |
| `white` 纯白 | `#fafafa` | `#ffffff` | `#18181b` | `#0b63f6` | v7 瑞士：白底 + 近黑 + 信号蓝 |
| `codex` 蓝黑 | `#0d1117` | `#161b22` | `#1158c7` | `#58a6ff` | GitHub 深色系；主色压深到对比度 6.4:1 |

深色主题额外处理了三件小东西：颗粒层 `mix-blend-mode: screen` 且降到 0.14、暗角加深、`.diag` 斜线减淡——
否则暖纸那套的"颗粒 + 压暗"在深底上会显脏。

### 10.2 切换器（三处入口）

- **页眉下拉**：`暖纸 · 尼尔 / 纯白 · 瑞士 / 蓝黑 · 专业`，任何屏都能切。
- **系统 → 配色**：三张卡（带色板，当前项描边），适合第一次发现这个功能。
- **键盘 `T`**：循环切换，并弹一条"配色已切换"的提示。
- 选择写进 `localStorage.v8.theme`，刷新/重开都保持。

### 10.3 顺带修掉的三个真问题

| 问题 | 现象 | 原因 / 修法 |
| --- | --- | --- |
| **运行台从来没有选中行** | 三套主题下都量不到 `.row.is-sel`；`W/S` 在运行台会取到 `rows[NaN]` | `UI.cur` 只有 mock/flow/… 的键，**没有 run/audit/gate** → `clamp(undefined)` = NaN → `i === NaN` 永远假。补键 + `renderList` 防 NaN + `selectRow` 守卫 |
| **蓝黑激活态对比度不足** | 激活页签 4.26:1（低于 4.5） | 主色 `#1f6feb` → `#1158c7`，白字对比度 5.95:1；键帽另立 `--key-bg`，深色下改中性灰，避免一片蓝 |
| **实时审计被挤出首屏** | 主区 600px 装不下"状态块 + 就绪链 + 触发台 + 审计" | ① 全就绪时把 4 格就绪链压成一行；② **触发台并入状态块**（接口下拉 + 触发按钮 + 状态行），少一整块；③ 待放行从满卡片改成一行摘要（详情留「闸门」屏）。结果：审计面板顶端 769 → **664**，可见流水 **0 → 5 行** |

### 10.4 验证

```
对比度（选中行 / 激活页签）：暖纸 4.8 / 8.67 · 纯白 16.97 / 16.97 · 蓝黑 11.21 / 5.95   （全部 ≥4.5）
九宫格溢出扫描：3 主题 × (375/1024/1600) × 10 屏                全部无横向溢出、pageerror = 0
切换链路：页眉下拉 ✓ · 系统屏卡片 ✓ · T 键轮换 ✓ · localStorage 持久化 ✓（刷新后仍是选中项）
合并后动作回归：触发一次 ✓ · 连发 3 次（日志 9→14）✓ · 停止/重启 ✓ · 折叠左右栏主区 512→1280 ✓
oracle 八版 8/8 通过；共享层单测 24/24
```

### 10.5 边界

- 三套主题共用**同一套几何**（硬边投影、直角、打孔线、菱形光标），只换色与阴影浓度——所以切换不会"跳版式"。

## 十二、R7：换色过渡（去掉那一帧硬闪）

用户反馈：*"瞬间切换，太闪了，有没有过渡效果？"*

### 12.1 做法

**只在一个窗口里开过渡**，而不是给 `*` 常驻 `transition`（后者会把 hover 也拖慢、还会在首次绘制时抖）：

1. 切主题时给 `html` 加 `is-theming`，此时 `*` 获得 300ms 的颜色过渡（`background-color / color / border-color / box-shadow / fill / stroke`）。
2. **双 `requestAnimationFrame`**：先让过渡属性生效，再改 `data-theme` token —— 否则同一个样式重算里改两次，浏览器不会补间，还是硬切。
3. 420ms 后摘掉 `is-theming`，避免常驻。
4. 同时叠一层很轻的"呼吸"：`.stage` 缩放 0.9985、透明度 0.94（45% 处回落），460ms 走完；颗粒层同步从 .34 抬到 .50 再回落——像纸被换了一张。

**密度切换**只重排不换色，用另一条 340ms 的压暗（`reflowVeil`，透明度降到 .86）遮住行高跳动。

### 12.2 缓动是重点：第一版还是"闪"

第一版用了 `cubic-bezier(.2,.8,.2,1)`（很常见的 ease-out），实测进度：

| 时间 | 70ms | 140ms | 210ms |
| --- | --- | --- | --- |
| 进度（第一版） | **93%** | 99% | 100% |

也就是前 70ms 就基本换完了 —— 观感仍是一次闪。改成 `cubic-bezier(.33, 0, .25, 1)` 并把时长拉到 300ms 后：

| 时间 | 50 | 100 | 150 | 200 | 250 | 300ms |
| --- | --- | --- | --- | --- | --- | --- |
| 进度 | 2% | 29% | 65% | 88% | 97% | 100% |

是一条均匀的 S 曲线，中段（150ms 附近）能明确看到"两者之间"的中间态，这才是"过渡"而不是"闪"。

### 12.3 遵守刚做的那套偏好

- 设置里**动效 = 关闭** → 不加 `is-theming`，直接切（实测切换过程中无该类）。
- **动效 = 精简** → 过渡与动画都压到 90ms。
- 系统级 `prefers-reduced-motion: reduce` → 过渡与呼吸全部 `none`。

### 12.4 顺手修一个我自己造成的问题

排查时发现 `app.js` 里**主题函数块存在两份**——早先有一次补丁脚本被我误跑了第二遍，锚点仍在，于是把整块又插了一次，
**后插入的旧版本覆盖了带过渡的新版本**（所以第一版加完过渡完全没反应）。删掉 23 行重复块后恢复正常。
教训：补丁脚本必须幂等（锚点删除式替换 + 跑前检查标记），这次也顺手给后续脚本都加了"已存在则跳过"。

### 12.5 验证

```
曲线采样   50→300ms 进度 2 / 29 / 65 / 88 / 97 / 100%（中线可见中间态）
类管理     is-theming 与 is-swap 在 ~350–420ms 内正确摘除，无残留
偏好联动   动效关闭时切换无 is-theming（瞬切）· 精简 90ms · reduced-motion 无动画
回归       换色后对比度仍全部 ≥4.5（过渡只改时间不改色值）· oracle 八版 8/8 · pageerror = 0
```

### 12.6 边界

- 过渡只作用于**颜色类属性**；背景图（颗粒、暗角、斜线）不做插值，靠颗粒脉冲掩盖。
- 连续快速切换（连按 T）时用 `_swapping` 闸门：上一次没走完就不叠新动画，直接赋值，避免抖动。
- 画布类内容（示波器）不在过渡范围内——它自己有帧循环，颜色变化会在下一帧跟上。
