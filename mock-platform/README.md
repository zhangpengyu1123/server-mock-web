# Mock 平台 · 八版设计前台

Windows 上部署的 mock 平台前端（给对端 Linux 网元系统做仿真调测）。
**同一个平台、同一批数据、同一套交互逻辑，八种完全不同的视觉语言。**

```bash
cd mock-platform
node serve.mjs                 # → http://127.0.0.1:4500/
```

打开 <http://127.0.0.1:4500/> 是导航页；八版各自独立：

| 变体 | 地址 | 设计方向 |
| --- | --- | --- |
| V1 | `/v1-ops-console/` | 暗场运维控制台（HUD / FUI · 深靛＋琥珀） |
| V2 | `/v2-swiss-editorial/` | 瑞士网格 · 编辑风（浅色，Swiss Modernism 2.0） |
| V3 | `/v3-rhine-lab/` | 莱茵生命 · 临床档案 / 终端（PRTS 维基语言，双主题） |
| **V4** | `/v4-archive-terminal/` | **莱茵生命 · 档案终端**（暖灰白＋近黑＋暖杏金 · 竖排刻度 · 解密扫描线） |
| **V5** | `/v5-music-console/` | **莱茵生命 · 音乐调测台**（晨雾/月影双主题 · 卡列＋底部 transport · 刻度尺导航） |
| **V6** | `/v6-mock-lab/` | **MOCK 实验台 · 信号链工作台**（极光玻璃 · 横向信号链＋可回放审计带＋人机交互闸门 · 晨雾/夜航双主题） |
| **V7** | `/v7-swiss-bench/` | **MOCK 检证台 · 瑞士版**（V6 的卡片结构 × V2 的瑞士语言：白底／近黑／信号蓝／宋体巨号 · 白昼/墨夜双主题） |
| **V8** | `/v8-blackbox-terminal/` | **BLACKBOX TERMINAL · 尼尔式**（截图精准还原：纸面 + 硬边投影 + 打孔虚线 + 菱形光标 + 方形键帽 + 启动自检屏 · 运行台/准备台双模式 · **三套配色可切**：暖纸 / 纯白 / 蓝黑） |

> **V6 是我自己的一版**：把平台做成一条**信号链**（对端 → 接入 → 能力矩阵 → 响应引擎 → 审计带），
> 底部是可回放的时间带，人机交互做成真的「闸门」。视觉用**极光玻璃**（柔美通透）而不是仪表机房，
> 动效严格只用 ui-ux-pro-max 技能的预设。

> V4/V5 是按用户给的两个莱茵生命仓库（博客主题 + 音乐台，同源于 RhineLabUI 上游）重做的，
> 用的是**真正的莱茵生命设计语言**（详见 [`_shared/RHINELAB-DESIGN-LANGUAGE.md`](_shared/RHINELAB-DESIGN-LANGUAGE.md)）。V3 保留为「PRTS 维基」这一对照方向。

## 一、为什么八版能对比

八版**共用一份共享层**（`_shared/`），所以差异全部来自设计，而不是数据：

```
_shared/
  domain.js                 领域数据 + 状态仓库 + 响应规则引擎 + 流量模拟器（八版共用，勿改）
  motion.js                 动效核心：spring / iris / develop / countUp / stagger / carry + 合成音效
  micro.js                  12 个微交互原语（mx-*），样式由各版自己写
  button-fx.js              按钮动效层（技能预设落地：hover/按下/掠漪/loading/禁用）
  fx.js                     Canvas 程序化特效：噪波 / 极光 / 网格渐变 / 扫描线 / 点阵 / 粒子 / 金属光泽
  README.md                 接口契约 + §5 六个界面的验收清单
  RHINELAB-DESIGN-LANGUAGE.md  莱茵生命设计语言（从三个上游仓库源码提取，V4/V5 施工依据）
```

八版的分工（oil-ui 的原则：两个方向在**布局、字体、颜色、关键意象**里最多只能共用一项）：

| | V1 暗场控制台 | V2 瑞士编辑风 | V3 莱茵生命（PRTS） | V4 档案终端 | V5 音乐调测台 |
| --- | --- | --- | --- | --- | --- |
| 布局 | 左导轨＋顶部遥测＋面板网格 | 顶部编号导航＋单栏编辑版面＋12 栏 | 顶部编号导航＋检定档案双栏 | **左侧竖排刻度导航＋档案面板** | **顶部品牌＋卡列＋底部 transport** |
| 字体 | Inter＋等宽 | Inter＋衬线大标题＋等宽 | 思源黑体＋拉丁展示字 | **MiSans＋等宽编号（460ms 滚动）** | **MiSans＋等宽（时间/流量）** |

## 二、六个界面与需求落点

| # | 界面 | 必须覆盖的功能（八版都要有） |
| --- | --- | --- |
| S1 | `mock` Mock 管理 | 注册本机 IP/端口 · **生成证书文件** · 挂载一种或多种平台能力 · 开启 mock 服务 |
| S2 | `flow` Mock 流程 | 请求/响应审计日志 · 定制**延迟**与 **HTTP status** · 面向对象的响应**字段**定制（下拉选 + 手工填写）· 字段级规则**自增 / 单次生效 / 条件** · **插入人机交互**并放行/拒绝 |
| S3 | `ne` 网元管理 | 属性/架构/类型 · 版本/软件名称/旧版本 · 升级流程步骤 · 步骤中的人机交互 · 网元成组 · 复制网元 · 参数校验 |
| S4 | `omp` 网元管理平台 | 受管网元与网元组 · 账号管理的网元范围 · 创建账号 · 创建一体化升级任务并关联站点 |
| S5 | `lcm` 生命周期平台 | 受管网元 · 软件包（类型/所属网元/厂商/版本）· 与网元管理平台**共部署** |
| S6 | `vlp` 虚层管理平台 | CPU 数量 · 主副站点 · 升级流程详情 · 平台版本 · 软件包校验流程 |

规则引擎（S2 的核心）由 `_shared/domain.js` 提供，五种规则三版都能配：

| kind | 名称 | 参数 | 效果 |
| --- | --- | --- | --- |
| `fixed` | 固定 | — | 每次同一个值 |
| `increment` | 自增 | 起点 / 步长 / 格式（`{n:04}`） | 第 n 次命中按步长累加 |
| `once` | 单次生效 | 次数 / 兜底值 | 首次返回设定值，之后兜底 |
| `conditional` | 条件 | 字段 / 运算符（等于·包含·非空·末尾为偶数）/ 命中值与否则值 | 按上游字段分派 |
| `random` | 随机 | 候选值 | 从候选里随机取 |

「手动触发一次请求」后，界面会展示每个字段的**命中说明**
（例如 `data.neId = GNB-HZ-4825（第 4825 次命中）`、`data.token = EXPIRED（已失效，返回兜底值）`）——
这是「规则真的在生效」的可视证据。

### 3.3 莱茵生命设计语言（V4 / V5 的正典依据）

用户反馈：「上一版（V3）的莱茵生命有点怪怪的，我更喜欢这两个仓库的风格」——原因很明确：
**V3 用的是明日方舟官方维基（PRTS）那套「蓝青 + 菱形 + 斜纹」的语言，而莱茵生命档案终端是另一套「暖灰白 + 近黑 + 暖杏金」的临床档案语言**。

所以我把 06 / 07 / 08 三个仓库的 `.css` / `.ts` 做了十六进制色值频次统计，提取出真正的色板与动效家族，
写成共享规范 [`_shared/RHINELAB-DESIGN-LANGUAGE.md`](_shared/RHINELAB-DESIGN-LANGUAGE.md)，V4/V5 按它施工：

| 角色 | 值（三仓一致） |
| --- | --- |
| 画布（暖灰白） | `#e8e5e1` / `#eae5e1` |
| 纸面 / 浮层 | `#fffaf5`、`#fff7ed`、`#ece9e4`、`#e7e3d9` |
| 主文字（近黑） | `#080a08`、`#171713`、`#24221f`、`#232722` |
| 次要 / 分隔 | `#74786f`、`#77756d`、`#8e897b`、`#a6a49c`、`#aaa59a` |
| **强调（暖杏金/琥珀）** | **`#a67d48`**（按下 `#9b7247`）、亮部 `#ffe3b2`、选区 `#cbb397` |
| 暖中灰 / 橄榄 | `#c1b8a7`、`#b4a18c`、`#d8c9b9`、`#938977`、`#565c46` |
| 暗色（月影/深夜） | 石墨 `#171713`、暖白 `#e9eef2`、muted `#9caabd`、细线 `rgba(208,226,243,.2)` |

- **字体**：MiSans（300/400/600/700）→ PingFang SC / 微软雅黑；编号与数字用等宽。为保持离线不引外部字体文件。
- **排字层级**（07 的 `DESIGN.md` 定义）：标题 22px · 分组 14px · 主操作 13px · 说明 12px · 辅助 11px。
- **形状**：1px 细线为主、几乎不用圆角；**按钮是「裸」的**（上游源码 `border:0; background:none; padding:0`），
  可点性靠排字与 hover 的刻度/琥珀变化表达。
- **动效家族**：编号滚动 460ms · `ContentTransition` 360ms · 详情 180ms · 弹窗 300/200ms · 页签 150/180ms；
  一律**临界阻尼、保留速度**；交互停止 2.5s 后进入**常态轻微波动**；**列间异步波峰**；减少动态效果 → 直接到位。
- **版权说明**：只使用色值、排字规则与运动数值，**未复制对方源码、未使用任何游戏素材或官方 logo**。

### 3.4 按钮动效：把技能的预设做成共享层（`_shared/button-fx.js`）

用户要求「使用 skill 添加按钮动效」。我没有各版各写一套，而是把技能给的三档 hover 预设 + 按下/loading/禁用规则
做成**一个共享模块**，八版通用（V1–V3 也已接入）：

| 技能规则 | 模块落点 |
| --- | --- |
| Hover Subtle：`y:-1`、`opacity:.9`、150ms、位移 <2px | `data-fx="subtle"`（默认档） |
| Hover Standard：`y:-4`、`scale:1.02`、阴影抬升、250ms、配反向补间 | `data-fx="standard"`（或 `.btn--primary`） |
| Hover Complex：磁吸、钳制 `*0.3`、**一屏 ≤1–2 个** | `data-fx="magnetic"`（超 2 个运行期告警） |
| 按下立即反馈（等价 `active:scale-95`） | `pointerdown` → `scale(.97)`（transport `.94`）+ 涟漪 + 音效 |
| 异步 >300ms 必须给 loading | `MP.btn.loading(btn, '签发中')`，**最短 300ms** 防闪烁，带 `aria-busy` |
| 禁用：降透明 + 改 cursor | 自动监听 `disabled` / `aria-disabled` |
| 只用 transform/opacity | 全部动效仅 `transform / opacity / box-shadow` |

实现细节：**事件委托**（document 上一套监听），所以界面重画频繁的表格/列表里**不需要重新绑定**，新插入的按钮自动生效。
与莱茵生命的克制语言一致：**只加动、不加装饰**——不改颜色、不填色块、不加圆角。

### 3.5 明日方舟官方网页设计系统（PRTS Design）—— V3 的正典依据

V3 的色板、字阶、间距、圆角、动效 token 与装饰语言**逐条取自**该规范（公开文档，文本 CC BY-NC-SA 4.0）：

- **双正典主题**：`档案`（亮）/ `终端`（暗）两套等价主题，同一个语义令牌在两套主题各有取值；
  强调色亮色用游戏内蓝 `#0098DC`、暗色用官网青 `#18D1FF`，次强调 `#FFD800`；
  中性阶取自游戏内 UI（标准按钮 `#313131`、亮色面板 `#f5f5f5`、深底 `#181818`、官网面板 `#1d1f20`）。
- **字体策略 Latin as ornament**：中文永远思源黑体、行高 1.7；
  拉丁展示字（大写）只做标题旁英文/编号/数值/水印；HUD 标签用方形字；
  **表格数据数字一律用正文字体 + `tabular-nums`，不用 HUD 字**（规范明确要求）。
- **方舟 = 直角**：圆角 `0px`，输入框 `2px` 是唯一例外；色条 4px；4px 栅格间距。
- **装饰语言**：左侧色条 + 1px 细框（用 `border-image` 直角拼接，**避免 border 在角上斜接出小斜边**）、
  45° 斜纹（危险/禁用）、半调网点、网格/点阵/扫描线、角标三角、黑白反转（主动作靠明度反转而非彩色）、
  拉丁装饰字（`.ak-overline` / `.ak-num` / `.ak-code-id` / `.ak-watermark`）、
  **菱形母题**（列表符号、加载涟漪、时间线节点——它是独立小图形，不是盒子的斜边）。规范禁止切角/斜切/斜带。
- **动效 token**：`80 / 150 / 250 / 400 ms` 四档 + 四条 `cubic-bezier`；`prefers-reduced-motion` 下全部缩到 0.01ms；
  加载指示用菱形涟漪；层级 z-index 100/200/1000/1500/2000/3000/4000。
- **版权说明**：只使用色值、字体策略、几何装饰与排版规则，**未使用任何游戏素材文件或官方 logo**（V3 的六边徽标是自己画的 SVG）。

## 四、八版共同遵守的硬要求

1. **零依赖、离线可跑**：纯 `index.html` + `app.css` + `app.js`，无 npm / 构建 / CDN / 外链字体。
2. **界面切换不硬切**：用 `iris()` 光圈或 `carry()` 连续过渡，配合 `develop()` / 本版签名动效。
3. **每版至少 8 个微交互原语**，且放在语义正确的位置（实测 V1 8 个、V2 11 个、V3 12 个、V4 10 个、V5 12 个）。
4. **按钮动效统一走 `MP.btn`**（技能预设落地）：默认 `subtle`、主行动 `standard`、一屏 ≤1–2 个 `magnetic`；
   >300ms 的异步必须 `MP.btn.loading`；禁用要降透明 + 改 cursor。
5. **动效纪律**：150–450ms 为主、退出比进入快、动效只表达状态与空间连续；
   `prefers-reduced-motion` 下全部归零（CSS 与 `MP.motion.reduced` 双保险）。
6. **体验**：可见 label、就近报错、**重画不丢焦点**（输入与拖拽期间不整块重画）、
   键盘可达 + `:focus-visible`、`aria-*` 到位、375/768/1024/1440 四档不横向滚动、图标一律内联 SVG。
7. **动作必有反馈**：toast（带引信与撤销）/ 状态形变 / 可选音效（`MP.sfx`，默认关闭）。

## 六、注意事项

- **字体**：为保持离线，八版只用系统字体栈（MiSans/思源黑体/苹方/微软雅黑、Oswald、等宽等）。
  莱茵生命原作自托管 MiSans（`misans-webfont@4.3.1`）与授权字体 Novecento，我们**不引外部字体文件**，
  系统缺字时会逐级回退，观感与规范原版略有差异。
- **数据是前端模拟**：`_shared/domain.js` 里的网元、软件包、日志都是种子数据 + 定时器模拟，
  用于把交互链路和规则引擎跑通；接真实后端时替换 `domain.js` 的 actions 即可，八版视图层不用动。
- **素材**：V4 的六边徽标、V2 的衬线大标题、V1 的扫描线背景、V5 的频谱都是自绘/自实现的，
  不含第三方素材，也未使用任何游戏素材或官方 logo。
- 八版共用 `_shared/`，**改共享层会影响八版**；要单版定制请在各自目录里覆盖。
