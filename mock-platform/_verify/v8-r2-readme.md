## 八、R2 重构：两种时间（**本次意图 = 改流程**，视觉沿用）

> 按 oil-ui-pro 的规矩，先写意图：**这次是改流程，不是优化视觉**。纸面 / 硬投影 / 打孔线 / 菱形光标那套**一个字没改**，
> 改的是「什么东西在什么时候出现」。所以下面的判断都以流程为准，视觉效果只做新增件。

### 8.1 为什么要改

用户原话：*"7 个模块全部堆在界面上，但它们有依赖关系；真正给用户呈现的只有 mock 的启动，和启动后的操作。那些编辑的活都不是在运行中干的，还有新增接口。"*

按手册「改流程」的第一步——**亲手动一遍并计数**（1600×900，同一台机器）：

| 指标 | 改前 | 说明 |
| --- | --- | --- |
| 启动主行动的纵向位置 | **913px** | 首屏 900 高，必须滚动才看见；同屏还堆着 4 个面板 |
| 找到「审计日志」要滚多远 | **1532px** | 它是引擎屏中列的第 **11** 个面板（前面是接口、配方、5 张字段卡、人机交互） |
| 平级页签 | **7 个** | 运行与配置同权，界面没回答"现在该做什么" |
| 全局运行状态 | 只有右侧小字「在服 0/3」 | 平台最重要的状态不显眼 |
| 运行中是否禁止编辑 | 不禁止 | 边跑边改，改了什么算不算生效也没说 |

### 8.2 按五种原因定位

1. **做决定的地方没有信息**：启动要判断"证书/能力齐不齐"，可按钮在页面最底，能力卡片在它上面两屏。
2. **功能长在用户不会去找的地方**：运行时最需要的触发与审计，被压在编辑面板最下面。
3. **流程形态与任务不匹配（主因）**：平台其实有**两种时间**——准备时（离线配置）与运行时（服务在跑）。原来那 7 个是**配置分类**，却被当成了导航。
4. **系统知道的事让用户再做一遍**：系统明明知道证书/能力是否齐备，却要用户自己逐屏核对。
5. **状态看不见**：运行/停止是第一状态，只藏在右侧面板的一行小字里。

### 8.3 新结构：两种时间 → 两个模式

```
[运行台] [准备台]                    ← 模式开关（页签条左侧两块）
  ├─ 运行台：  运行 · 审计 · 闸门 · 系统        （运行时只看这 3+1 个）
  └─ 准备台：  接入 · 接口 · 网元 · 平台 · 库房 · 虚层 · 系统
```

**首屏 = 运行台**（这是运行时唯一入口）：
1. **运行状态大块**：`运行中 / 已停止` + 地址 · 能力数 · 请求数 + 主行动（按住启动 / 停止）。
2. **就绪链**：`① 端点已登记 → ② 证书已签发 → ③ 能力已挂载 → ④ 服务运行中`。
   完成的打勾；**未完成的那一步高亮**，点它直接跳到准备台对应位置（运行中会被拦，提示先停止）。
3. **触发台**：选接口 → 触发一次，下面给出状态/延迟/命中/是否插了人机交互。
4. **实时审计**：最新请求 + **待放行卡片内联放行/拒绝**；右上「全部记录」进审计页。

**准备台 = 离线编辑**：六屏原样保留，但**运行时被锁**——页签变灰加删除线，点击提示"停止后才能编辑"，
页眉常驻「运行中 · 准备台已锁」+ 一键「停止并进入准备」。

**内容迁移表**（谁搬去哪）：

| 原来住的地方 | 现在住的地方 |
| --- | --- |
| 接入屏底部的「伺服 / 启动服务」 | **运行台 · 主行动** |
| 引擎屏的「触发一次」 | **运行台 · 触发台** |
| 引擎屏的「审计日志」 | **运行台 · 实时流** ＋ **审计页**（完整过滤/搜索/详情） |
| 引擎屏的「放行 / 拒绝」 | **运行台 · 待放行卡片** ＋ **闸门页**（集中处理） |
| 其余全部编辑能力（登记/证书/能力/配方/字段/规则/交互/网元/账号/包/虚层） | **准备台 · 六屏** |

### 8.5 验证

```
oracle（功能 30 条 + 动效 + 微交互 + 按钮动效 + 离线 + 语法）        V8 通过
浏览器 5 档(375/768/1024/1440/1600) × 10 屏                          全部无横向溢出、pageerror = 0
模式：运行中点「准备台」→ 被拦 + 提示；页眉「停止并进入准备」→ 停服并落到接入屏 ✓
准备台·接口屏：已无触发按钮、无审计面板 ✓（运行时的东西不在编辑区）
运行台·停止态：主行动出现、就绪链高亮下一步、触发台显示"服务停止中" ✓
布局实测：.work 56→1544、右列 1104→1544（440 宽贴右）、锁提示 262×28 横排 ✓
```

**本轮修掉的 4 个布局/接线问题**（都是自己验证时抓到的）：

1. **隐藏页签仍占位** —— `[hidden]` 的 UA 规则被 `.tab{display:flex}` 覆盖 → `.tab[hidden]{display:none!important}`；
2. **舞台隐式网格列被页眉内容撑宽**，右列被裁掉 56px（视觉上一眼就看出状态面板被切）→ `.stage{grid-template-columns:minmax(0,1fr)}`；
3. **锁提示被挤成竖条**（`margin-left:auto` 在满排页签里拿不到宽度）→ 移入页眉 + `white-space:nowrap`；
4. **页签被压窄导致标题截断**（"运.."）→ `.tab{flex:0 0 auto; min-width:132px; max-width:210px}`。

> 一行 `req` 拼错、事件监听没挂、`SEL.ne()` 语义误解这三个更早的坑，是 R1 阶段抓的，已记在上文。

### 8.8 已知边界与假设

- **假设 1（运行中禁止编辑）**：用户说"编辑的活都不是在运行中干的"，因此实现为**硬锁**（不是只读提示）。
  如果真实产品允许热改接口（比如改完提示"需重启生效"），把锁换成"可编辑但标注未生效"即可，结构不用动。
- **假设 2（默认落在运行台）**：首屏即运行时视角。若主要用户是"每天来配一次、跑一天"，也可反过来默认准备台。
- 演示种子里 `port-1` 是运行态，所以打开就是「运行中」；要看启动链路，点一次「停止并进入准备」→ 回运行台即可。
